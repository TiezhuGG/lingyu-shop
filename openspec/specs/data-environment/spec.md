# 本地真实数据验证环境

## 当前能力

- 独立 Compose 项目 `lingyu-shop-dev` 提供 PostgreSQL 17.11、Redis 8.2.10，镜像通过补丁标签加官方 index digest 固定。实际验证架构为 linux/amd64。
- PostgreSQL 仅暴露 127.0.0.1:15432；Redis 仅暴露 127.0.0.1:16379。数据使用独立命名卷；随机开发密码保存在忽略的 `.env`。
- `db:poc` 仅接受 loopback PostgreSQL 的 `lingyu_shop_poc` 库，拒绝业务库、远程地址、连接参数或 schema 覆盖。无效 URL 报错不含输入凭证。
- 工程迁移可在空库部署，并在容器保留卷重启后重复部署。工程表 CHECK 阻止负数。
- 参数化行锁保证 20 请求竞争 1 份仅一个成功；异常事务回滚。Prisma 真实死锁及 Serializable 冲突均通过有限的整笔事务重试恢复，失败尝试没有残留写入。
- Prisma 原生查询冲突使用已验证的 P2010 嵌套 adapter SQLSTATE 映射；普通写冲突为 P2034。非冲突错误不重试。
- 两连接池被真实并发事务使用，结束时无等待请求。探针原子创建自有两行，拒绝覆盖旧行，等待所有并发任务结束后清理，仅清理本次行。
- `redis:poc` 检查 AOF/noeviction、随机键 WAITAOF 落盘、停机连接不可用、正常重启后恢复和自有键清理，不清空数据库。

## 边界与恢复

这不是商城库存、业务数据库、生产备份或高可用验收。PoC 重试器暂在工程脚本中，生产事务端口由 T01-D 交付；不得直接用脚本替代业务幂等和审计。

数据库正常停止使用 Compose stop，恢复使用 up -d --wait；不删除卷、reset 或反向删除迁移。失败探针如遗留行，应先确认归属及是否还有运行进程，再按运行手册检查，不能自动覆盖。Redis 测试只覆盖正常重启，不证明断电恢复。
