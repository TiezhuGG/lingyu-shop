# T01-D3：事务上下文、有限重试与审计端口

状态：完成；T01-D2 的真实 API/数据库验收已通过。本子项不实现身份、商品、订单、Outbox 或外部调用。

## 目标与边界

`DatabaseService.runInTransaction` 是后端应用服务唯一的事务入口。回调每次尝试获得新的、不可跨请求保存的 `TransactionContext`；它不暴露根 PrismaClient、任意表 CRUD 或 HTTP/contracts 类型。后续模块把同一上下文传给各自公开写服务，仓储不得在内部另起事务。

只有确定为并发冲突的 Prisma `P2034`，或已在 T01-C2 实测的 `P2010` 内 SQLSTATE `40001`/`40P01`，才能重试整个回调；最多 3 次，线性短退避。连接中断、提交结果未知、约束错误和任意业务错误不重试，交给后续业务幂等键和查证流程。每次重试创建新的上下文，且不会把前一尝试的副作用带入下一次。事务采用 PostgreSQL Serializable 隔离级别及受配置数据库超时限制的等待/执行时间。

本子项的唯一业务库表为基础设施拥有的 append-only `audit_log`，并非订单、库存或身份事实。它保存 UUID、来源（API/Worker）、可空 actor 类型/ID、动作、对象类型/ID、可空 requestId/业务幂等键、调用方已脱敏的标量 changes 与创建时间；为对象、requestId、idempotencyKey 建索引。审计端口只允许通过同一 `TransactionContext` 追加，公开 API 没有更新或删除接口。拒绝访问类安全事件仍由未来身份模块的独立安全日志处理，不能依赖已回滚事务的审计。

审计输入限制为枚举/白名单字符串和小型扁平标量变更摘要；拒绝原始请求体、凭证、地址、支付资料和任意嵌套 JSON。D3 只能验证“追加审计和回调工作一起提交或一起回滚”的基础语义；具体业务模块仍必须在自己的规格中声明表归属、锁顺序、幂等键和哪些变更已经脱敏。

## 迁移、恢复与验证

Prisma schema 与迁移放在已有 `packages/server-modules/prisma` 业务边界。迁移可对空的 `lingyu_shop`/`lingyu_shop_test` 部署，不接触工程 PoC 库，也不 drop/reset。升级失败时停止应用，修正并以新增前向迁移恢复；应用回退需兼容新增的独立审计表。`db:migrate:deploy` 使用同一业务迁移目录，真实测试在运行前部署迁移。

常规测试验证重试分类、次数上限、审计输入脱敏限制及审计端口不接受失效上下文。真实 PostgreSQL 测试用独立 `lingyu_shop_test`：成功提交后只有一条审计；回调抛错后无残留；首个可重试失败后的第二次成功只留下第二次的一条审计；非可重试失败不重复执行。测试只清理带本次随机 requestId 的自身审计行，并延续既有连接隔离/故障恢复保护。

事务回调中禁止网络、文件、消息投递和其他不可回滚副作用；后续 T12-A Outbox 提交后消费。当前 API 的契约工程探针不调用审计或事务端口，避免把基础验证伪装成商城行为。
