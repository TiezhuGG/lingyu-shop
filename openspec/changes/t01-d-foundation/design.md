状态：D1 已实施并通过验收（详见 backend-foundation spec）；D2/D3 仍为待实现设计。T01-C2 已完成；本文后续事务、审计和 HTTP 契约不代表当前能力。

## 边界和连接生命周期

`packages/server-modules/src/foundation` 提供 ConfigModule、DatabaseModule、AuditModule 等后端能力，API/Worker 仅装配公开模块。仓储实现拥有自己的表，不能暴露任意表写接口。backend-shared 定义小型类型/事务端口，contracts 只输出客户端数据结构；两者不得反向依赖 server-modules。

业务 `DATABASE_URL` 必须显式配置，不能自动回退到 POC_DATABASE_URL；工程 PoC 表/专用库不承载商城事实。T01-D 接入前建立独立开发业务库及测试库，工程迁移与业务迁移目录/客户端边界须明确，不把旧 PoC 全量迁移到业务库。

API 与 Worker 各有自己的 Prisma/pg 池并配置上限；总连接预算为 API 实例数×池上限 + Worker 实例数×池上限 + 运维预算。启动时校验 URL、pool/timeout/port 等范围；readiness 通过带超时的 SELECT 1，liveness 只证明进程存活。终止时停止接入与轮询、等待在途事务、断开数据库，超时退出需有日志。

## 事务端口

应用服务入口调用 `runInTransaction(operation)`，operation 获得不可跨请求复用的事务上下文。同一上下文传给本次编排涉及的所有模块公开服务，仓储不得在内部另起事务，也不得使用根 PrismaClient 绕过上下文。事务上下文只在后端传递，不进入 contracts。

将已通过 T01-C2 的结构化错误映射迁入正式实现；P2034/已验证 SQLSTATE 才能重试整个事务，最多 3 次、退避并记录次数。事务内禁止网络、文件上传和任何不可回滚副作用；后续外部调用由提交后的 Outbox 驱动。提交结果未知/连接中断不能按死锁盲重试，交给业务幂等键查证。每个业务任务定义锁顺序与幂等约束，公共重试不能代替这些规则。

## HTTP 与客户端契约

每个请求生成 requestId；只接受长度和字符白名单内的上游 ID，否则替换，防止日志注入。统一 JSON 错误结构为 `{ code, message, requestId, details? }`；400 输入错误、401 未认证、403 越权、404 不存在、409 版本/幂等冲突，未知异常只输出稳定内部错误。日志不记录凭证、完整请求体、SQL 参数或用户真实隐私。开发身份和生产身份严格分离，由 T02 实现。

DTO/schema 是校验与 OpenAPI 的单一来源；在 T01-D2 验证生成器版本及 DCloud TS 兼容性后锁定，生成接口类型和薄客户端到 contracts，禁止另写同名手工 DTO。首个探针为无业务副作用的工程端点，覆盖未知字段、字符串金额、枚举与错误结构；不得以工程探针充当商品能力。前端传输 `*Minor` 十进制字符串，不转浮点计算。

## 审计与迁移

审计追加包含 actor/source、action、对象 ID、requestId、业务幂等键、必要脱敏变更及时间。成功操作的审计与业务事实同事务；拒绝访问的安全事件通过独立日志记录，不能假定已回滚事务会保存日志。审计服务不提供修改或删除业务流水接口。

迁移规格先定义每张基础表归属/索引/唯一约束、空库与升级库验证、回退应用兼容和数据前向修复步骤；不以 drop/reset 恢复。T01-D 不创建未知订单、积分或营销表。
