# T03-B：固定 SKU 草稿、价目与发布

## 范围与依赖

依赖已验收的 T01-D、T02-B、T03-A0/ADR-003；单 ONLINE 销售范围，不要求真实门店。交付分类配置、SPU/固定包装 SKU/规格选项、Pricing 草稿与发布价目、后台编辑/发布/下架，以及用户端真实公开商品只读列表。不自动导入经营商品/售价，不开放下单；搜索、规格选择、可售库存、购物车、图片资产/CMS、执行履约分别留后续任务。没有库存事实时明确“库存未接入、暂不可购买”，不称有货。

分类为一级配置，名称/排序/归档有版本；公开商品保存发布当时的分类快照，分类修改不偷改既有发布。最多 100 分类；商品列表游标分页，不静默截断。SPU 保存名称、纯文本说明及 1～30 个固定 SKU；选项最多 3 个轴，同 SPU 轴一致、组合去重，NFKC/去首尾空白后按轴排序。单位为件/包/盒/瓶/袋，数量按包装正整数；规格可写包装净含量但不作称重换算。SKU ID/code/unit/options 创建后不可变、不可删除；停用保留身份，新增规格创建新 SKU，以免将来库存/车的相同 ID 改成不同商品。

## 契约与发布

统一 OpenAPI/生成类型/服务端 AJV，拒绝未知字段和伪造范围/主体。PUT 分类/商品使用客户端稳定 UUID 和 expected version（首次 0）；重放/并发同版本最多一笔成功，其余 409。商品草稿金额可留空（不是零）；显式非负整数分十进制字符串，最大 999999999999，禁止浮点或隐式免费。发布须商城已配置、分类有效、有至少一个启用 SKU 且每项价格齐全。

保存草稿、发布、下架均递增聚合版本。发布创建不可覆盖的商品/分类/启用 SKU 快照与 Pricing 价目版本，原子切换 publishedVersion；后续编辑只改草稿，公开继续读指定发布快照与对应价目。下架清空指针，公开立即消失，历史保留。发布/下架使用独立 catalog.sku.publish 权限，保存需 catalog.write，读取需 catalog.read；权限都绑定同一销售范围，不以 GLOBAL IAM 代替。接口复用 Cookie/Origin/CSRF，公开与后台均 no-store。

## 表归属、事务与恢复

Catalog 拥有 catalog_category/product/sku/publication/published_sku；Pricing 独立拥有 sku_price_draft/sku_price_version，Catalog 只通过 Pricing 公开事务接口保存/查询/发布金额；Store 只通过 readInTransaction 读取配置。共享同一 Serializable 上下文与有限重试，无事务内外部副作用。

锁顺序沿用 IAM 事务锁→主体/会话行→Catalog 聚合→按 SKU ID 排序的 Pricing，版本条件更新保证冲突失败；新建 ID/代码/组合唯一冲突转 409。成功业务/每项价格变化/发布金额摘要与审计同事务；审计不写名称/说明/选项全文。失败回滚全部业务和成功审计，受控拒绝另记脱敏审计。已发布数据只追加，不提供任意覆盖/物理删除接口。

追加迁移（不编辑既有迁移），FK/唯一/CHECK 约束 scope、单位、非负金额、正版本；空 schema 全量迁移与现存测试库升级均验收。回退旧应用保留新增表/数据，前向修复；不 drop/reset，不删除业务数据来恢复。生产迁移、备份恢复和容量压测另验收。

## 验收

1. DTO/规范化：整数分边界、空价格、重复代码/规格、未知字段、固定单位/身份不可变、分页输入。
2. 真实 PostgreSQL/API：空目录无 seed、分类/商品持久化、越权/只读/CSRF、过期编辑与并发 409、草稿不公开、发布价格版本一致、二次编辑不污染旧快照、下架立即消失、审计失败全回滚、数据库约束、进程重启恢复与撤权拒绝。
3. 后台实际表单保存/重载/发布/下架，公开 H5 能读到同一 SKU/金额，空/加载/失败有反馈；临时测试账号与商品仅用隔离库并精确清理。
4. check/build/typecheck/test/test:database/contracts:verify/H5 构建、全部 tracked/untracked diff 审阅；不把 H5 当微信真机，不把公开展示当库存/交易验收。
